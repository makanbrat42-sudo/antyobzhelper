# VK: вход сотрудников и VK-бот

## 1. VK ID (OAuth 2.1 + PKCE)

Используется для входа сотрудников (`/login`) и для подтверждения VK кандидатами (`/link`).

1. Откройте [id.vk.com](https://id.vk.com) → «Мои приложения» → создайте приложение, платформа **Web**.
2. Базовый домен — домен сайта; **доверенный Redirect URI**: `https://<домен>/api/auth/vk/callback` (для локальной проверки — `http://localhost:3000/api/auth/vk/callback`, если VK ID разрешит localhost).
3. Скопируйте ID приложения в `VK_ID_CLIENT_ID`. Защищённый ключ не нужен: используется PKCE.
4. `VK_ID_BASE_URL` по умолчанию `https://id.vk.ru`.

Как работает: сервер генерирует `state` и `code_verifier` (подписанная httpOnly-cookie, 10 минут), перенаправляет на `/authorize`, затем обменивает код на токен через `/oauth2/auth` и получает профиль через `/oauth2/user_info`. VK ID берётся только из ответа серверов VK. Токены VK не сохраняются.

> Реальный вход через VK ID не проверен — на момент разработки не было приложения VK ID. Обмен кода протестирован только юнит-тестами формата PKCE; при первом запуске проверьте вход и сообщите об ошибке, если VK вернёт нестандартный ответ.

## 2. VK-бот сообщества

1. Создайте сообщество (или используйте существующее). Управление → **Сообщения**: включите. Управление → Сообщения → **Настройки для бота**: включите «Возможности ботов».
2. Управление → **Работа с API → Ключи доступа**: создайте ключ с правом «Сообщения сообщества» → `VK_GROUP_TOKEN`. ID сообщества (число) → `VK_GROUP_ID`.
3. Работа с API → **Callback API**:
   - Версия API: 5.199
   - Адрес: `https://<домен>/api/integrations/vk/callback`
   - Строку, которую должен вернуть сервер, → `VK_CALLBACK_CONFIRMATION` (задайте в Vercel и передеплойте **до** нажатия «Подтвердить»)
   - Секретный ключ: придумайте → `VK_CALLBACK_SECRET`
   - Типы событий: **Входящее сообщение** (`message_new`), **Действие с сообщением / callback-кнопка** (`message_event`), **Разрешение / запрет сообщений** (`message_allow`, `message_deny`).
4. На сайте: «Руководство КП» → добавьте сотрудников, включите «Принимать» / «Отклонять». Нажмите ✈ «Проверить» — бот отправит тестовое сообщение.
5. **Каждый получатель** должен разрешить сообщения от сообщества: открыть сообщество → «Написать сообщение» / «Разрешить сообщения». Иначе VK вернёт ошибку 901 — она будет видна в «Руководство КП» и «VK-бот → Ошибки доставки».

### Поведение
- Новая заявка уходит в **личные сообщения** каждому участнику «Руководства КП» с включённым «Получать заявки». В беседы бот не пишет.
- Кнопки «✅ ПРИНЯТЬ» / «❌ ОТКЛОНИТЬ» — callback-кнопки. При нажатии сервер берёт VK ID из события, заново проверяет: активный сотрудник, право RBAC, флаг в «Руководстве КП», статус заявки. Решение применяется атомарно; второй нажавший получает «Заявка уже обработана».
- После «Отклонить» бот просит причину следующим сообщением (15 минут, «-» — без причины).
- После решения разосланные сообщения редактируются: показывается решение и кто его принял, кнопки убираются.
- Сообщения от не-сотрудников (включая кандидатов) бот игнорирует и не отвечает.
