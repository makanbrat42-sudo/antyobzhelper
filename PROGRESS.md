# PROGRESS — AntyObzhelp

Обновлено: 01.11.2026

## Реализовано

**Этап 1 — основа.** Next.js 16 + TypeScript + Tailwind 4, Prisma 7 + PostgreSQL. Схема БД (`prisma/schema.prisma`): сотрудники, должности, разрешения, сессии, регистрации, руководство КП, кандидаты, заявки, ответы, решения, закрепления, обзвоны, результаты, ограничения, комментарии, хронология, журнал, уведомления, события и доставки интеграций, настройки, сервисные токены. Уникальные ограничения для атомарности: одна активная заявка на кандидата, одно решение на заявку, одно активное закрепление, один идущий обзвон, идемпотентность ответов Google Forms и событий VK. Локальный PostgreSQL без Docker. Тёмный интерфейс в заданной палитре.

**Этап 2 — доступ.** VK ID OAuth 2.1 + PKCE, сессии в httpOnly-cookie (хеш токена в БД), заявки на регистрацию, страница ожидания, защищённая первоначальная настройка администратора (`SETUP_TOKEN`, блокировка от гонки). RBAC: 18 разрешений, 9 основных должностей и 3 должности обзвонщиков, индивидуальные выдачи/запреты, редактирование должностей и цветов бейджей. Нельзя выдать право, которого нет у себя; нельзя снять последнего администратора.

**Этап 3 — интерфейс.** Dashboard с графиками, «На рассмотрении», «Ожидают обзвонщика», «Мои заявки», карточка заявки, отчёт, история кандидатов, сотрудники и профили, рейтинг, админ-панель (регистрации, Руководство КП, должности, VK-бот, Google Forms, API и Discord, настройки, журнал). Модальные окна, toast, skeleton, адаптивное меню, обновление в реальном времени (SSE).

**Этап 4 — приём заявок.** HMAC-подпись, проверка структуры, идемпотентность, повторные доставки, защита от дубликатов, автоотказ `AUTO_REJECTED_COOLDOWN` (120 ч, источник SYSTEM, причина и даты сохраняются, руководству и в очередь не попадает). Определение VK: код подтверждения (VERIFIED) / ссылка / короткое имя; противоречивые и неподтверждённые совпадения — ручная проверка VK ID. Google Apps Script с очередью повторов.

**Этап 5 — VK-бот.** Рассылка в личные сообщения участникам «Руководства КП» (получатели из БД), callback-кнопки, повторная проверка полномочий при каждом нажатии, атомарное решение, «Заявка уже обработана», запрос причины отказа, обновление разосланных сообщений, учёт ошибок доставки (в т.ч. 901), повтор по cron. Кандидатам бот не пишет.

**Этап 6 — обзвоны.** Атомарное «Взять на себя», начать/завершить/перенести, результаты ✅❌🚫⏳, серверное время и длительность, комментарии, переназначение и возврат в очередь, копирование VK и Discord-приглашения, отметка «Кандидат уведомлён» (без отправки сообщений).

**Этап 7 — отчёты.** Отчёт заявок с колонкой «Кто принял / отказал» (ник со ссылкой на профиль, «Система» для автоотказа, «—» без решения), фильтры, поиск, сортировка, пагинация, CSV. История кандидата по VK ID, действующие ограничения и дата повторной подачи, снятие ограничения. Рейтинг за сегодня/неделю/месяц/всё время.

**Этап 8 — публикация.** API для Discord-бота с сервисными токенами, `vercel.json` (cron), `vercel-build`, `.env.example`, бэкапы (скрипт + GitHub Actions), документация в `docs/`.

## Проверки (выполнены на этом компьютере)

- `npm test` — 83 теста, все проходят: 5-дневное ограничение (2 дня, 4 дня, за минуту до 120 ч — автоотказ; ровно 120 ч и 6 дней — разрешено; отказ руководства, перенос, отказ кандидата — без ограничения), дубликаты в каждом активном статусе и при параллельной подаче, идемпотентность, одновременные решения, одновременное закрепление, права, VK Callback (подпись, повтор события, кнопки, причина отказа), отсутствие сообщений кандидатам на полном цикле, отчёты, история, статистика.
- `npm run typecheck`, `npm run lint` — без ошибок.
- `npm run build` — успешно.
- `npm run smoke` — 38 сквозных HTTP-проверок против dev-сервера, все прошли.
- Скриншоты основных страниц (компьютер и телефон) без ошибок в консоли браузера.

## Не проверено (нет реальных настроек)

- Вход через **настоящий VK ID** — нужен `VK_ID_CLIENT_ID`.
- **Настоящий VK API** (отправка/редактирование сообщений, callback-кнопки) — проверено на имитации API VK.
- **Настоящая Google-форма** и Apps Script — проверено подписанными запросами к эндпоинту.
- Развёртывание на Vercel/Supabase.

## Требует вашего участия

1. Установить Git, создать **приватный** репозиторий, сделать первый коммит ([docs/DEPLOY.md](docs/DEPLOY.md)).
2. Создать приложение VK ID и сообщество с ключом и Callback API ([docs/VK.md](docs/VK.md)).
3. Создать проект Supabase и проект Vercel, задать переменные окружения.
4. Подключить Apps Script к форме ([docs/GOOGLE_FORMS.md](docs/GOOGLE_FORMS.md)).
5. Назначить себя администратором через `/setup`, затем удалить `SETUP_TOKEN`.
6. Решить, подходит ли Vercel Hobby (некоммерческое использование) — иначе Pro или VPS.

## Найденные и исправленные ошибки

- Пререндер API-маршрутов при сборке (Next 16 Cache Components) — маршруты помечены `connection()`, служебные ошибки Next пробрасываются.
- Клиентские хуки навигации вне `<Suspense>` ломали сборку — оболочка панели обёрнута в Suspense.
- Файлы встроенной БД внутри проекта перезапускали dev-сервер — данные перенесены в `%LOCALAPPDATA%`.
- Карточки статистики, обёрнутые ссылкой, не растягивались по сетке.
